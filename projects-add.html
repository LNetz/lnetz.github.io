    01 Agile Data Development

    2018 — 2022

    Designing a wind turbine means thousands of parameters, CAD files and simulation results passed between specialists — often by e-mail. We built a single point of truth for this engineering data, generated from a model the customer can change on their own.

    • The problem

      In wind-turbine engineering many disciplines work on the same machine: mechanics, electrics, control, simulation. Their parameters depend on each other, and a value changed in one place has to reach every other. In practice it travelled as e-mail attachments and files on individual laptops — outdated values crept in, and past simulation results were hard to find again. Agile and plan-driven development had to come together on one reliable data basis.

    • The cockpit

      The result is a web cockpit — an engineering digital twin “as designed” — where engineers look up, edit, version and release parameters, CAD files and simulation results. A change history and archive, a release lifecycle (draft → review → released → outdated) with a check that released objects only point to released objects, and a diff view keep every value traceable. A Python library connects the engineering tools themselves — Rhino, Ansys, SpaceClaim — so they read and write the data through the API instead of local files.

    • Generated from one class diagram

      ADD was the first real project for CD2GUI, an extension of MontiGem that derives the user interface from the class diagram: for every class, a navigation, an overview and an editing page. Engineers had a clickable prototype within days, and the customer could extend the data schema — which grew to more than 120 classes and 200 relations — and simply regenerate. Where generic pages were not enough, hand-written GUI models and charts were added on top, such as the views of simulation results below.
