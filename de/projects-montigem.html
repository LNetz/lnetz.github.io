01MontiGem

2018 — 2024

Daten und Seiten in kleinen, präzisen Modellen beschreiben — und eine vollständige Webanwendung bekommen: Datenbank, Java-Backend, API und Angular-Frontend. MontiGem ist der Generator hinter den meisten meiner Projekte.

  • Die Idee

    Betriebliche Informationssysteme sehen von außen verschieden aus, bestehen aber immer wieder aus denselben Teilen: Datenklassen, Persistenz, Validierung, eine API, Listen, Formulare und Detailseiten. Diese von Hand zu schreiben ist langsam, repetitiv und fehleranfällig — und jede Änderung an der Domäne zieht sich durch alle Schichten. MontiGem (MontiCore-based Generator for Enterprise Management) generiert sie stattdessen, aus einem Klassendiagramm für die Daten, GUI-Modellen für die Seiten und optionalen OCL-Constraints für die Validierung.

  • So funktioniert es

    Der Generator folgt der klassischen Compiler-Pipeline (Abbildung oben). Von MontiCore generierte Parser machen aus jedem Modell einen Syntaxbaum; Modell-zu-Modell-Transformationen formen ihn in die Struktur des Zielcodes um; FreeMarker-Templates geben ihn als Java, TypeScript und HTML aus. Für jede Domänenklasse entstehen so eine JPA-Datenklasse, ein DAO, ein Builder, ein Validator, DTOs und die Commands der API — auf dem Server und identisch auf dem Client. Jedes GUI-Modell wird zu einer Angular-Seite. Die generischen Teile — Laufzeitkomponenten, Styling, Authentifizierung mit Apache Shiro — stammen aus einer handgeschriebenen Laufzeitumgebung, die nie neu generiert wird.

  • Generiert und handgeschrieben

    Kein Generator deckt alles ab — die spannende Frage ist also, wie handgeschriebener Code hineinpasst. MontiGem nutzt den TOP-Mechanismus: Schreibt eine Entwicklerin eine Klasse mit dem Namen einer generierten, gibt der Generator seine Version stattdessen als …TOP aus, und die handgeschriebene Klasse erbt davon. Generierter und handgeschriebener Code liegen in getrennten Ordnern; die ganze Anwendung kann jederzeit neu generiert werden, ohne eine einzige Zeile zu verlieren.

    // generated, because Account.java exists in the handwritten folder
public class AccountTOP { … }

// handwritten — survives every regeneration
public class Account extends AccountTOP {
  @Override
  public BigDecimal getBalance() { … }
}

  • Fünf Domänen

    MontiGem entstand innerhalb von MaCoCo und wurde später zu einem eigenständigen Framework herausgelöst — die erste Version habe ich gemeinsam mit Simon Varga und Kai Adam gebaut. Seitdem wurde es in fünf Domänen eingesetzt, die jeweils neue Funktionen in den Generator zurückgebracht haben:

    • MaCoCo — Finanz-, Personal- und Projektmanagement für Lehrstühle; OCL-Validierung.
    • Ford — IoT-Werkzeugverfolgung; mehrsprachige Oberflächen und eine fahrsichere Tablet-Ansicht.
    • Agile Data Development — Windkraftanlagen-Entwicklung; CD2GUI generiert die Seiten aus dem Klassendiagramm.
    • Energiemanagement von Gebäuden und InviDas — der Vergleich von Datenschutzerklärungen von Wearables.

    In [Net24] ist MontiGem das letzte Glied einer Kette: Ein LLM macht aus einer natürlichsprachlichen Beschreibung ein Klassendiagramm, CD2GUI leitet die GUI-Modelle ab, und MontiGem generiert die Anwendung — vom Text zur laufenden Web-App. Wie das funktioniert.
