01MontiGem

2018 — 2024

Describe the data and the pages in small, precise models — and get a complete web application: database, Java back end, API and Angular front end. MontiGem is the generator behind most of my projects.

  • The idea

    Business information systems look different on the surface but are built from the same parts again and again: data classes, persistence, validation, an API, lists, forms and detail pages. Writing these by hand is slow, repetitive and error-prone — and every change to the domain ripples through all layers. MontiGem (MontiCore-based Generator for Enterprise Management) generates them instead, from a class diagram for the data, GUI models for the pages and optional OCL constraints for validation.

  • How it works

    The generator follows the classic compiler pipeline (figure above). MontiCore-generated parsers turn each model into a syntax tree; model-to-model transformations reshape it into the structure of the target code; FreeMarker templates print it as Java, TypeScript and HTML. For every domain class this yields a JPA data class, a DAO, a builder, a validator, DTOs and the commands of the API — on the server and, identically, on the client. Each GUI model becomes an Angular page. The generic parts — runtime components, styling, authentication with Apache Shiro — come from a hand-written runtime environment that is never regenerated.

  • Generated and handwritten

    No generator covers everything, so the interesting question is how hand-written code fits in. MontiGem uses the TOP mechanism: if a developer writes a class with the name of a generated one, the generator emits its version as …TOP instead, and the hand-written class extends it. Generated and hand-written code live in separate folders; the whole application can be regenerated at any time without losing a single line.

    // generated, because Account.java exists in the handwritten folder
public class AccountTOP { … }

// handwritten — survives every regeneration
public class Account extends AccountTOP {
  @Override
  public BigDecimal getBalance() { … }
}

  • Five domains

    MontiGem grew inside MaCoCo and was later extracted into a framework of its own — I built its first version together with Simon Varga and Kai Adam. It has since been used in five domains, each of which pushed new features back into the generator:

    • MaCoCo — financial, staff and project management for university chairs; OCL validation.
    • Ford — IoT tool tracking; multi-language UIs and a driving-safe tablet view.
    • Agile Data Development — wind-turbine engineering; CD2GUI generates the pages from the class diagram.
    • Energy management of buildings, and InviDas — comparing the privacy policies of wearables.

    In my dissertation MontiGem is the last link of a chain: an LLM turns a natural-language description into a class diagram, CD2GUI derives the GUI models, and MontiGem generates the application — from text to a running web app.
